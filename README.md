# idea-to-delivery · 从想法到成果

一个通用的 Agent Skill：把模糊的想法推进成**有依据、可检查**的成果，减少重复解释与返工。

适用于研究方案、课程项目、产品概念、原型、PPT、报告和口播稿。单纯格式转换、局部润色，或已有明确规格的制作任务，不必走完整流程。

## 它解决什么

想法阶段真正昂贵的问题往往不是「做得不够多」，而是**在没确认方向之前就投入了批量制作**，然后返工。

这个 Skill 让 Agent：

- 先恢复事实（当前记录、已有成果、相关反馈），再接续项目，而不是重新走一遍立项
- 判断**哪一个不确定性最值得先解决**，再决定要不要做研究、做成什么规模
- 在目标、方向取舍、内容结构、最终样稿四个节点把选择权交回给你，而不是替你做方向决定
- 交付后检查**真实文件和实际运行结果**，不轻信工具的成功提示
- 用一份持续更新的项目记录替代反复总结，避免每轮生成新文档

## 安装

```bash
npx -y skills add lianlele168/idea-to-delivery -g --all
```

## 使用

装好后直接描述你的想法即可，例如：

> 我有个念头：……，现在很模糊。帮我理清楚该先验证什么。

也可以显式调用：`$idea-to-delivery`

接续旧项目时，直接说「继续上次那个」——它会先去读项目记录，不会让你重述。

## 主要边界

- 不替代专门的文档、设计、开发或制造工具
- 默认由**一个** agent 完整执行；不以增加 agent 数量或文档数量作为进展
- 不会把「尚未验证」写成「做不到」，也不会把「需求不强」改写成「删除」
- 区分最终愿景、当前验证、当前交付三种范围；缩小样本不等于缩小产品愿景

```
└── references/
    ├── project-record.md           项目记录与跨 agent 交接的最小模板
    ├── research-and-decisions.md   研究方法选择、证据身份、方向讨论结构

    └── deliverables.md             PPT / 报告 / 口播 / 软件原型 / 实体的验收要点
```

## 依赖

无。核心方法只依赖阅读、讨论与交付能力，不假定存在某个模型、联网、文件系统、摄像头或子代理 API。
